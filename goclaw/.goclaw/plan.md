Tu objetivo es analizar un proyecto completo que contiene archivos Markdown (.md) con documentación (requisitos, decisiones técnicas, TODOs, arquitectura) y código fuente.

### CONTEXTO

- Los archivos .md contienen la intención del sistema, reglas de negocio, decisiones de diseño y posibles mejoras.
- El código puede no estar alineado con la documentación.
- El proyecto debe evolucionar iterativamente hacia mejor calidad, mantenibilidad y consistencia.

2. Analizar el código fuente actual
   - Detectar code smells (duplicación, funciones largas, acoplamiento, etc.)
   - Identificar desviaciones respecto a la documentación

   - Aplicar cambios en el código
   - Explicar brevemente qué se mejoró y por qué

   - Clean Code

   - KISS

   - Tests básicos si no existen

   - 📌 Módulo trabajado

   - ✅ Cambios aplicados
   - 💡 Mejora futura sugerida
   - 📄 Código refactorizado

   - NO reescribir todo el proyecto de golpe
   - Iterar paso a paso (tipo pipeline evolutivo)
   - Priorizar impacto vs riesgo
   - Mantener coherencia con lo definido en los .md

- Leer → Analizar → Refactorizar → Validar → Repetir
